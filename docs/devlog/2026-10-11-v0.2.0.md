# v0.2.0: Accounts and a home

*2026-10-11, Paul Carouge*

**Accounts.** Sign-in, password reset and an optional second factor (a code sent by email).
PocketBase allows public sign-up by default; for a private, self-hosted instance that is the wrong
default, so a migration closes it: the administrator creates accounts. Password reset never reveals
whether an address has an account.

**A home.** The interface got its shape: a sidebar with the sections to come, an account menu with
the theme (light, dark, system) and language, and a split sign-in page. Everything is built from
the design tokens, and every page is checked by axe for WCAG 2.2 AA in the end-to-end tests.

**What went wrong.** Changing the theme quietly re-ran the app's startup (server check, session
refresh) because an effect happened to read the theme. Clicking a theme button also closed the menu:
the click re-rendered its own target, which then looked like a click outside. Both were caught by
tests written for the menu, not for those bugs.
