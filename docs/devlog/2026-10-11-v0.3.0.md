# v0.3.0: A drive that survives a bad connection

*2026-10-11, Paul Carouge*

**Uploads that resume.** Large files on home connections fail. Uploads use the tus protocol: the
server (tusd embedded in the binary) stores chunks, and an interrupted upload continues where it
stopped, even after closing the tab. Names, folders and sizes are validated before a single byte is
stored; when the last chunk arrives, the server creates the file, computing its size, type and
SHA-256 from the content rather than trusting the browser.

**A drive.** Folders, breadcrumbs, rename, trash with restore (purged after 30 days) and live
updates: change something in one tab and it appears in the others. Downloads use the real file
name, accents included.

**What went wrong.** Adding the upload route made the server panic at startup: Go's router saw it as
ambiguous with the web app's catch-all route. Unit tests did not register the web app, so only the
end-to-end tests and the Docker smoke test caught it; a new test now builds the full router.
The PocketBase SDK also dropped live updates after navigating between folders (unsubscribing and
resubscribing the same topic in one tick loses the new listener), so the app now keeps a single
subscription and fans events out.
