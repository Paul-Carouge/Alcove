# v0.10.1: Not every ffmpeg is the same

*2026-10-12, Paul Carouge*

v0.10.0 was published, then the continuous integration went red on a single test: HEIC photos.

On my Mac and in the Docker image, ffmpeg is version 8. On GitHub's Ubuntu machines it comes from the
system packages, version 6.1, and it refuses the test picture with "Invalid data found when processing
input". Phones don't store a HEIC photo as one image but as a grid of small tiles, and ffmpeg only learned
to put those tiles back together in version 7.1.

The test was right to fail: anyone who installed Alcove natively on Debian 12 or Ubuntu 24.04 and let the
installer add ffmpeg from the system packages would have had the same problem, with an error message
that explains nothing. Alcove now checks the ffmpeg version once, says plainly that HEIC needs 7.1 or
newer, and the test is skipped where that is not available. Videos and other photos are not affected, nor
is the Docker image.

Still open: offering a recent ffmpeg to native installs on those systems, rather than only documenting
the limit.
