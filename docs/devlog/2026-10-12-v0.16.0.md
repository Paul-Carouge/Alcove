# v0.16.0: Every photo, once

*2026-10-12, Paul Carouge*

This is the release the mobile app was started for. Turn on **Photo backup** and the phone copies its
photos and videos to your server, in the quality they were taken, and keeps doing it.

## What it does

The first time, it goes through the whole library, newest first. After that, only new pictures. It runs
when you open the app, when you tap "Back up now", and on Android roughly every hour in the background,
on Wi-Fi only if you prefer. Files land in a "Phone backup" folder, and from there in the timeline, the
map and the duplicates finder like any other photo. Nothing on the phone is ever changed or deleted.

## Every photo, once

A backup that uploads the same picture twice is worse than none: it fills the disk and the duplicates
page. So before uploading, the app computes each file's fingerprint (SHA-256) and asks the server which
ones it already has. Photos you uploaded from the web are skipped; so is everything after a reinstall,
when the app has forgotten what it did. A photo you deleted on the server is not brought back either: the
trash counts.

Uploads use the same resumable protocol as the web (tus): a train tunnel in the middle of a two-gigabyte
video costs a few seconds, not the whole file.

## Getting the real file

Phones like to hand apps a convenient copy. The backup asks for the original: the HEIC from an iPhone, the
video as recorded. On Android there is a catch: unless the app asks for one more permission, the system
silently removes the GPS position from every photo it reads. The app asks, so photos keep their place on
the map.

An integration test runs the whole backup against a real Alcove server: two files uploaded, then a
"reinstall" that uploads nothing, then a check that the server read the photo's date and location.

## What went wrong

- **Two saves at once.** The backup records each upload's address as soon as it starts, so an interrupted
  upload can resume. That save ran at the same time as the next one, both writing the same temporary file;
  one of them failed. Saves now queue up.
- **A name taken.** I called the backup class `BackupService`; the PocketBase SDK already has one (for
  server backups). It is `PhotoBackup` now.
- **A quoted keyword.** The server-side "which files do you have" query asked the database for a column
  literally named `DISTINCT sha256`. The query builder quotes names; distinct is a separate option.
