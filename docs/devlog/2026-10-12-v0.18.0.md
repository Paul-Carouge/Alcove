# v0.18.0: An app you can just install

*2026-10-12, Paul Carouge*

Until today, trying the phone app meant installing Flutter, or me building a file and serving it over the
home Wi-Fi. From this release on, every GitHub release carries **`alcove-android.apk`**, and the web app
links to it: Account → Alcove on your phone.

## A key that must never be lost

Android only installs an update over an app signed with the same key. Lose the key, and every user has to
uninstall (and lose their settings) to update. So the app has its own release key, generated once and kept
like the server's update-signing key: in the repository's secrets for the release machine, and in a private
folder on mine. The release workflow decodes it, builds and signs the APK, and deletes it again.

## Home networks without HTTPS

The installer offers a "local network" mode where the server answers on `http://machine:8090`. The phone app
refused that address outside of development builds, which made that mode useless with the real app. Plain
http is now accepted for addresses that can only exist on a private network (192.168.x.x, 10.x.x.x,
Tailscale's 100.64.0.0/10, `nas.local`, a bare `nas`…), with a visible warning that the connection is not
encrypted. Any public address still needs HTTPS, and the test list includes the tricky ones next door
(172.32.0.1, 100.128.0.1, `local.example.com`).

## Also on the phone

Albums arrived on mobile, yours and the ones shared with you, and the viewer can move one of your photos
to the trash (with a confirmation, and 30 days to change your mind from the web).

## What went wrong

Nothing broke this time. One decision is pending: the iPhone app needs an Apple Developer account and a Mac
with the full Xcode; it will come when those exist.
