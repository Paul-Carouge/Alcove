# v0.19.0: An app that keeps up

*2026-10-12, Paul Carouge*

Two requests for this release: make the phone app feel premium, in the same spirit as the web app, and let
it update itself.

## One version, one source

A sideloaded app has no store to push updates. The obvious idea, checking GitHub from the phone, has two
problems: a home server reached over Tailscale may serve phones that should not need the internet, and the
"latest" app is not necessarily the one that matches the server. So the app follows its server instead. It
asks which version the server runs; if it is newer than itself, it offers the update. The server downloads
the APK of its own release once, keeps it next to its data and serves it to every phone. Updating the server
is enough: phones follow at their next launch.

Integrity comes from Android itself: an update is only accepted if it is signed with the same key as the
installed app. That is why the signing key of v0.18.0 matters so much, and why it is backed up twice.

## Premium is mostly details

The redesign is a list of small things rather than one big idea: titles that start large and shrink into the
bar as you scroll, settings in rounded groups with tinted icons, photo tiles with slightly rounded corners
that fade in instead of popping, month headers that stay pinned, a ring that shows backup progress, a photo
viewer that turns everything black and hides its controls when you tap. Albums became a tab of their own.

## What went wrong

- To judge a design you have to look at it, and there is no phone emulator on this machine. The answer was a
  set of screenshot tests that render every screen in light, dark and English with a fake server. They paid
  off at once: every button label rendered as black boxes. In tests that is just a missing font; on a real
  phone it meant buttons used Roboto while the rest of the app used Inter. Flutter's button styles replace
  the text style instead of inheriting the app's font.
- The account screen showed "Made by Paul Carouge" twice, which a test caught.
- The server held one lock both for its version cache and for the 60 MB download of the app, so a phone
  asking "is there an update?" would have waited for another phone's download to finish. They now have
  separate locks, and APKs of older versions are removed when the server starts.

The update path needs a published release, so it only comes to life once the repository is public. Until
then the app simply says it is up to date.
