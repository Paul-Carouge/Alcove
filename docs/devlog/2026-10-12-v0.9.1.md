# v0.9.1: The version that wasn't

*2026-10-12, Paul Carouge*

Right after v0.9.0 shipped, the continuous integration went red on a test that passed locally: the
System page never announced the (fake) newer release.

The CI clones the repository without its tags, so `git describe` had no version to describe and the
binary called itself `f3cc7b2`. A commit hash is not a version, and the updater, being careful, refused
to compare it with anything. Anyone building Alcove from a shallow clone would have had the same silent
problem: no update would ever be offered.

Builds without a tag are now `0.0.0-dev`, a version that any real release outranks, and the updater
treats anything it cannot read the same way. The CI fetches tags again. And the fix itself needed a fix:
in a Makefile, the `#` of the shell expression `${v#v}` starts a comment.

The published v0.9.0 binaries were not affected: they carry their version from the release tag. Their
signature was checked against the key compiled into Alcove after publication.
