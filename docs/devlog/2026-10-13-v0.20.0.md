# v0.20.0: Finding the words

*2026-10-13, Paul Carouge*

Phase 3 starts: documents. A self-hosted drive is where leases, invoices and scanned letters end up, and
the only way to find one was to remember its file name. Now the words inside them can be searched.

## Shipping Tesseract like ffmpeg

The original plan (ADR 0007) put OCR in a separate container. Since then most installs became native, a
single binary installed with one command, and a container would have made OCR a Docker-only feature. The
answer was already in the repository: ffmpeg ships as a signed bundle of unmodified Alpine packages with
their own libraries, verified like the binary and updated with it. Tesseract and poppler fit the same mould:
24 MB compressed, French and English models included, and the same archive runs on Debian, Ubuntu or
Fedora. Rather than copy the ffmpeg installer, it became a generic one that both bundles use.

## What gets read

PDFs are read twice if needed: their text layer first, which is instant, and OCR only when a page has
almost no text, which is what a scan looks like. Images are trickier. Reading every photo would keep a
Raspberry Pi busy for days and find mostly nothing, so the rule is simple: images without camera metadata
(screenshots, scans) are read, camera photos are not. Text files are read as they are.

Everything goes into SQLite's FTS5 index with accents removed, so "depot" finds "dépôt", and every word
is a prefix, so "fact" finds "facture". What the user types is never passed to FTS5 as a query language:
quotes and operators are just characters.

## What went wrong

- The test documents had to be invented. ffmpeg here has no text filter, so a small Go program draws the
  text with a system font, and a Python script wraps the picture in a PDF by hand, with no library. No real
  document is in the repository.
- The first end-to-end run failed on a button that was "not stable". It was stable; the upload panel in the
  corner was simply covering it. The test now clears finished uploads, like a person would.
- On phones, hiding the "Text" label with `display: none` left an empty button, and worse, a button without
  a name for screen readers. The label is now only visually hidden.
- The new search page wrote "1 result· 1 inside a document": Svelte had swallowed the space.

Also in this release: dropdowns are now drawn by Alcove rather than the browser, whose open list cannot be
styled in Firefox, and checkboxes, radio buttons and switches finally match the rest of the design.
