# v0.26.0: Installing on a blank machine

*2026-10-14, Paul Carouge*

A robustness release: edge cases, a look at performance, and installing Alcove on a machine that has
nothing on it, the way someone new to self-hosting would.

## A fresh Debian

The installer was run in an empty Debian container, then the installed server was started as its own
user. It worked, and showed three things a beginner would trip on:

- The setup link read `http://0.0.0.0:8090/setup`. That address means "every interface" to a server and
  nothing to a browser. The installer and the server now print the machine's real network addresses,
  home network first, then Tailscale, with `name.local` as a fallback.
- Without a certificate store, reaching GitHub failed with an x509 error that explains nothing. It now
  says to install `ca-certificates`.
- The fallback that installs ffmpeg with apt failed on a fresh system because apt had never fetched its
  package lists. It runs `apt-get update` first.

The Docker image was built and started too: healthy, with ffmpeg 8, Tesseract (French and English) and
poppler inside.

## Edge cases

- **Same names at once.** When several uploads named `photo.jpg` finish together, each picks the next free
  name, but two can pick the same one. The server retried once, so the third could fail. It now retries
  up to five times, with a test that saves six files with the same name in parallel.
- **Empty files.** A zero-byte upload is complete the moment it is created, so the server answers with the
  new file right away and forgets the upload. The phone then asked the server about an upload that no
  longer existed. It now reads the answer to the creation.
- **Names from everywhere.** Accents, emoji, Japanese, a leading dot, 254 characters: all stored as sent;
  slashes, tabs, ".." and 256 characters refused.
- **A phone left on for days.** The app refreshed its session only at launch; a token that expired while
  the app stayed open made every screen fail. It now renews the session when the app comes back, and goes
  to the sign-in screen if the session was revoked.

## Performance

The web app's largest dependency, the map library, was already loaded only on the map. The second, the
upload client (16 kB compressed), was loaded on every page; it now arrives with the first upload.

## What went wrong

- The first test of names with emoji failed, and looked like a real bug: the files went to the root
  folder. They did, because the test picked files before the folder page had replaced the root page.
  Waiting for the page fixed the test; the product was fine.
- The new "6 B" sizes broke two tests that expected "6 byte", as they should have.
