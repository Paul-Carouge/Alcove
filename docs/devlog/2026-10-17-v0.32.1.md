# v0.32.1: The allocation before the read

*2026-10-17, Paul Carouge*

v0.32.0 shipped the Google Photos import after three rounds of review. The last round of fixes had not
been reviewed itself, so it got a fourth look the same day, and that look found one more way in.

The defence against hostile archives was a reader that refuses to give Go's zip parser more than 48 MB
while it reads the archive's directory. It works for the directory. But before reading a single directory
entry, Go prepares a list sized from the entry count the archive *announces* in its last bytes, as long
as that count looks possible for the file's size. A 40 GB upload whose final 144 bytes announce over a
billion entries made the parser reserve about 11 GB of memory after reading 1,244 bytes. On Linux that
can kill the whole server, and the import retried, so it could happen again.

Alcove now reads the announced count itself, following the exact steps Go uses to find it, and refuses
the archive before Go sees it. An import that stops the server three times also quarantines its
archives, so the same files cannot be used to try again.

Nobody else ran v0.32.0 (the repository is still private), but the fix ships as its own release so the
history says what changed and why.
