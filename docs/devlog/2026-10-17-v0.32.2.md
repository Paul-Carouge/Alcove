# v0.32.2: A flaky test that was right

*2026-10-17, Paul Carouge*

One test of the app's upload queue failed on CI for the second time in three days, each time a little
differently. The first time, it checked the queue file before the queue had finished cleaning up, and the
test was taught to wait. This time it failed reading the queue file itself: "Unexpected end of input".

The test was not the problem. The app wrote its queue of pending uploads straight over `queue.json`. Read
during that write, the file is half there, and so it would be for the app if Android closed it at that
moment: at the next start, the damaged file is ignored and every pending upload is forgotten.

The queue is now written to a temporary file, flushed, and renamed over the old one, which is all or
nothing. Leftover temporary files from an interrupted save are removed at the next start.
