# v0.34.0: One folder for the photos

_2026-10-18, Paul Carouge_

## What

The photo library now lives in a single root folder of the drive, "Photos". Google Photos imports go
to "Photos/Google Photos/<year>", the phone backup to "Photos/Phone backup" ("Sauvegarde du téléphone"
in French), and the update moves existing folders there. Files also shows real thumbnails for HEIC
photos and videos, and opens HEIC photos in its viewer.

## Why

**A drive confused with a photo library.** Each photo feature created its own root folder: the Takeout
import made "Google Photos", the app made "Phone backup", and people often add a "Photos" folder by
hand. After an import, the root of Files was mostly photos, with the user's own files in between.
One "Photos" root folder keeps the library browsable as files (useful for downloads, moves, sharing)
without taking over the drive. The name is the same in English and French, so the server, the app and
the migration agree on it without translation. A migration moves the known folders of every user into
their "Photos" folder, reusing one they made. Apps already backing up are unaffected: they remember
their folder by id, and a move keeps the id.

**Thumbnails that were already there.** The media worker has made upright JPEG thumbnails and previews
of every photo and video since 0.11, HEIC included (ffmpeg 7.1+). Photos used them; Files did not. It
asked PocketBase for thumbnails, and PocketBase cannot read HEIC or videos, so iPhone and recent
Android photos showed as file icons, and the viewer could not open them at all. Files now looks up the
media records of the photos on screen, in batched requests (one per 50 files, shared by every thumbnail
rendered in the same tick), and falls back to PocketBase while the worker has not finished. PNG, GIF
and WebP keep PocketBase thumbnails, so transparency and animation survive; JPEGs use the worker's,
which apply the EXIF orientation.

## What went wrong

The review found that the app looked up its "Photos" folder with a case-sensitive filter, while drive
names are unique regardless of case. A user with a "photos" folder would have had every backup fail on
a duplicate name; the lookup now uses `name:lower`. The migration had the same blind spot, and could
have split the library over several "Photos (N)" folders when a file named "Photos" sat at the root.
In the viewer, opening a JPEG downloaded it twice (PocketBase thumbnail, then the preview), a HEIC
flashed "no preview" for a moment, and an iPhone `.mov` would have opened as a still picture. All fixed
before release.

Left for later: a thumbnail shown before the worker finished does not refresh by itself (it does on the
next change or visit); a backup folder renamed by hand stays at the root; a root file named "Photos"
makes each Takeout import create a new "Photos (N)" folder.
