# v0.35.1: One missing await

_2026-10-21, Paul Carouge_

## What

The app's image loader (`FreshTokenImage`) now evicts an image from Flutter's image cache when its
bytes fail to decode, as it already did when the download failed.

## Why

`_load` returned `decode(...)` without `await` inside its `try` block. The returned future failed
after the block had exited, so the `catch` that evicts failed images never ran for a corrupt or
truncated file: the broken image stayed cached until the app restarted. A new Flutter lint,
`unawaited_return_in_try_block`, flagged it. A new widget test serves three bytes as an image and
checks that the cache lets it go.

## What went wrong

The lint had been failing the `mobile` CI job on `main` since 0.33.0, unnoticed: that job only runs when
mobile files change, which on `main` meant the release commits (they bump `pubspec.yaml`), and the
release workflow itself does not depend on CI. Local `flutter analyze` also crashes on paths with
non-ASCII characters (the analysis server miscounts the JSON message length); `dart analyze` runs the
same rules and works.
