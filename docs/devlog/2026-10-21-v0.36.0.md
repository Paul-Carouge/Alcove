# v0.36.0: The trash in your pocket

_2026-10-21, Paul Carouge_

## What

The mobile app has a Trash page, reached from the account menu behind the profile icon. It lists what
is in the trash: files, folders and photos (photos are drive files, so they share the drive's trash),
then notes. Each item can be restored or deleted for good after a confirmation, and the whole trash
can be emptied. The prompts shown when moving something to the trash now point to this page instead
of the web app.

## Why

On a phone, a deleted file or photo could only be brought back, or removed for good, from the web
app. Notes already had a trash in their own tab; they now also appear in the shared page so
everything deleted is in one place. The calendar has no trash: deleting an event removes it at once,
on the web too, and that stays as it is.

Restoring follows the web app: the item goes back to its folder, or to the root when that folder was
deleted or is itself in the trash. Only a missing folder (404) sends it to the root; any other error
while checking the folder stops the restore, so nothing lands somewhere unexpected.

## What went wrong

A review caught two bugs before release. Trashing a file, then its folder, lists both. Emptying the
trash deletes the folder first (newest first), and the server's cascade takes the file with it, so the
next delete got a 404 and was reported as a failure. A 404 on delete now counts as deleted, and the
list reloads afterwards. The rows also stayed tappable while the trash was being emptied: a file
restored in that window would still have been deleted by the loop. They are now inert until it ends.
The web app's "Empty the trash" has the same false failure and is left for a later fix.
